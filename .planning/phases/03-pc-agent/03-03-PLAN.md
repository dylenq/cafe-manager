<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Server push to agent | The agent trusts hub commands (authenticated by the shared key on connect) |
| agentsettings.json / CLI to agent | Local config holds the shared key and the emergency hash |
| Simulator to server | Dev tool using the same key as real agents |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-11 | Denial of service | Agent reconnect loop | medium | mitigate | Backoff caps at 30 s forever so a down server is never hammered; 401 also retries slowly; connect storms avoided in the simulator by staggering |
| T-03-12 | Tampering | Emergency unlock hash | high | mitigate | PBKDF2-SHA256, 200000 iterations, random 16-byte salt, constant-time compare; stored iteration count bounded to 100000..5 million so a tampered config cannot hang the agent; empty hash disables the feature |
| T-03-13 | Elevation of privilege | Local clock manipulation by a player | medium | accept | The countdown is cosmetic and the server is authoritative: server Lock/Grace always wins on a connected agent; only a disconnected agent relies on its own clock, and skew is corrected from ServerUtcNow at receipt |
| T-03-14 | Information disclosure | SharedKey in logs and error text | medium | mitigate | Loader errors and controller logs never contain the key; tested by grep and unit tests |
| T-03-15 | Repudiation | Agent self-lock at zero while disconnected | low | accept | Documented behavior: a server blip never kicks players out early; the lock at zero is the safe default |
| T-03-SC | Tampering | NuGet installs (Microsoft.Extensions.Logging.Console) | high | mitigate | Microsoft first-party, pinned 10.0.15; legitimacy recorded as a human-check (nuget.org owner "Microsoft"), not a blocking checkpoint, because research is disabled |
</threat_model>
