    NativeMethods (internal static, DllImport with explicit CharSet and SetLastError where relevant): SetWindowsHookEx, UnhookWindowsHookEx, CallNextHookEx, GetModuleHandle, GetAsyncKeyState, EnumDisplayMonitors, GetMonitorInfo (MONITORINFO with RECT), SetWindowPos, AttachConsole is already in Program.     KeyboardBlocker (IDisposable): Install() sets WH_KEYBOARD_LL (13) with a delegate kept in a field so the GC cannot collect it, from the UI thread; Uninstall() removes it and is idempotent. The callback reads the KBDLLHOOKSTRUCT, derives alt from the LLKHF_ALTDOWN flag, ctrl and shift from GetAsyncKeyState, asks KeyBlockPolicy and returns 1 to swallow, otherwise CallNextHookEx; any exception inside the callback is caught and the key passes through (the hook must never fault the input stack); the callback does no I/O and no logging on the hot path.

    LockWindow (code only, no XAML): borderless (WindowStyle None, ResizeMode NoResize), Topmost, ShowInTaskbar false, dark background, centered text: cafe name (very large), station name, the LockInfo reason (large), and a big clock updated by a one-second DispatcherTimer (local time). It is positioned over its monitor in physical pixels with SetWindowPos (HWND_TOPMOST) on SourceInitialized so DPI scaling cannot leave gaps. Closing is cancelled unless the application is exiting. Deactivation re-activates the primary window while locked. PreviewKeyDown detects the emergency chord and raises an EmergencyRequested event. EmergencyUnlockDialog (code only): modal, topmost, PasswordBox, OK and Cancel, a checkbox "Also exit the agent", 3 wrong attempts impose a 30 second lockout with the button disabled and a countdown text, the dialog never echoes the code and never logs it. It verifies with EmergencyCodeHasher.Verify against the configured hash; when the hash is empty it shows "Emergency unlock is not configured on this PC." and does nothing else.

    WpfLockScreen (ILockScreen): marshals every call to the UI dispatcher (BeginInvoke) because AgentController calls from SignalR threads. Show(LockInfo) creates one LockWindow per monitor (or updates text when already shown), installs the KeyboardBlocker, and subscribes to Microsoft.Win32.SystemEvents.DisplaySettingsChanged to rebuild the windows when monitors change; Hide() uninstalls the hook, closes (allowed) every window and unsubscribes. On a successful emergency unlock it calls AgentController.EmergencyUnlock and, when requested, AgentApplication.Exit. Document in a code comment that the hook is installed only while locked so games are never affected.

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-----------|-----------------|
| T-03-21 | Elevation of privilege | Escaping the lock overlay | high | mitigate | Per-monitor topmost windows, re-activation on deactivation, low-level hook swallowing Win, Alt+Tab, Alt+Esc, Ctrl+Esc, Alt+F4 and Ctrl+Shift+Esc via a tested KeyBlockPolicy; Closing cancelled; Ctrl+Alt+Del cannot be hooked and Task Manager policy is Phase 7 (DEPL-02), documented in README |
| T-03-22 | Tampering | agentsettings.json readable by players | medium | accept | The shared key lets a player impersonate an agent only on the cafe LAN; mitigation is NTFS permissions set by the Phase 7 installer; README advises admin-only access; key regeneration is one click in /settings |
| T-03-23 | Spoofing | Emergency unlock brute force | high | mitigate | PBKDF2-SHA256 hash (plan 03-03), 3 attempts then a 30 s lockout in the dialog, code never echoed or logged, feature disabled when no hash is configured |
| T-03-24 | Denial of service | Toast stealing focus from games | medium | mitigate | WS_EX_NOACTIVATE, ShowActivated false, Focusable false, never listed in Alt+Tab |
| T-03-25 | Denial of service | Hook faulting the input stack | medium | mitigate | Hook callback catches all exceptions and passes the key through; installed only while locked; delegate pinned in a field |
| T-03-26 | Tampering | Invalid config unlocking the PC | medium | mitigate | Configuration errors keep the PC locked and show the error text (never the key); logged to agent log |
| T-03-SC | Tampering | NuGet installs (Microsoft.Extensions.Logging) | high | mitigate | Microsoft first-party, pinned 10.0.15; legitimacy recorded as a human-check (nuget.org owner "Microsoft"), not a blocking checkpoint, because research is disabled |
