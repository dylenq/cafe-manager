    1. Self-elevate like install-server.ps1, passing every bound parameter through the same single-quote-safe quoting (values may contain `$`, `&`, `"` or spaces).
    2. Resolve `-GamingUser` to a SID with `[System.Security.Principal.NTAccount]::Translate([System.Security.Principal.SecurityIdentifier])`; stop with a clear message if the account does not exist.

Hash the code: `Start-Process -FilePath <exe> -ArgumentList '--hash-code', <quoted code> -Wait -PassThru -NoNewWindow -RedirectStandardOutput <temp file>`; read the first non-empty line, delete the temp file in a finally block, verify the exit code is 0 and the line matches `^pbkdf2-sha256\$\d+\$[A-Za-z0-9+/=]+\$[A-Za-z0-9+/=]+$`, otherwise abort with a message (never echo the code).

ACL on that file: inheritance removed, full control to SYSTEM (`*S-1-5-18`) and Administrators (`*S-1-5-32-544`), read-only to the gaming user SID (T-07-12 mitigation of tampering: the gaming user can read but not change the server URL or hash; the agent itself runs with highest privileges). Also grant the gaming user Modify on `$InstallPath\logs` (created here) so the agent can write logs.
    6. Register the scheduled task "CafeManager Agent": `New-ScheduledTaskAction -Execute <exe> -WorkingDirectory $InstallPath`, `New-ScheduledTaskTrigger -AtLogOn -User <account>`, `New-ScheduledTaskPrincipal -UserId <account> -LogonType Interactive -RunLevel Highest`, `New-ScheduledTaskSettingsSet -AllowStartIfOnBatteries -DontStopIfGoingOnBatteries -ExecutionTimeLimit ([TimeSpan]::Zero) -RestartCount 999 -RestartInterval (New-TimeSpan -Minutes 1) -MultipleInstances IgnoreNew -StartWhenAvailable`; `Register-ScheduledTask -Force` (re-run replaces the task).
    7. Task Manager policy: when the user's hive is loaded (`Test-Path "Registry::HKEY_USERS\<SID>"`), set `DisableTaskMgr` DWORD 1 under `Software\Microsoft\Windows\CurrentVersion\Policies\System` (create the key). Otherwise load `C:\Users\<profile>\NTUSER.DAT` (profile path from `HKLM\SOFTWARE\Microsoft\Windows NT\CurrentVersion\ProfileList\<SID>` `ProfileImagePath`) with `reg.exe load HKU\CafeManagerTemp`, set the value under that temp hive, then in a finally block force `[GC]::Collect()`/`WaitForPendingFinalizers()` and `reg.exe unload HKU\CafeManagerTemp` (retry 3 times with a short sleep because a lingering handle blocks unload); if the profile does not exist yet (user never logged in) print a warning that the policy must be applied after first logon by re-running the script, not a failure.
    8. If the gaming user has an interactive session (`Get-CimInstance Win32_ComputerSystem` UserName equals the account, or quser output), start the task now with `Start-ScheduledTask`; otherwise say it starts at that user's next logon. Do not add a firewall rule (outbound is allowed by default; documented).
    9. Final summary lines: install path, task name, user, server URL (never the key or code).
    uninstall-agent.ps1: parameters `-GamingUser` (default invoking user), `-InstallPath`; self-elevates; stops and unregisters the task (`Unregister-ScheduledTask -Confirm:$false`, tolerate missing), stops the `Cafe.Agent` process, removes `DisableTaskMgr` for that user's hive (same load/unload logic, tolerate missing key), deletes `$InstallPath` (retry for locked files) and the empty parent, and leaves `%ProgramData%\CafeManager\agent` unless `-RemoveData`. Share logic by duplicating the small helpers (each script must be copy-paste runnable on its own). Commit nothing.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| operator -> install-agent.ps1 parameters | shared key and emergency code pass through arguments |
| gaming user -> agent files/registry | a customer-level account sits on the same PC as the installed agent |
| build machine -> zip | the artifact leaves the dev machine |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-07-12 | Tampering / Information Disclosure | agentsettings.json | high | mitigate | File ACL: SYSTEM and Administrators full, gaming user read-only (cannot redirect the agent or swap the hash); install folder is under Program Files (admin-write only). The key stays readable to the agent's own user: accepted, documented |
| T-07-13 | Information Disclosure | release zip | high | mitigate | build-release safety scan fails the build on any .db/-wal/-shm file, a populated SharedKey in agentsettings.json, or log files in the stage |
| T-07-14 | Information Disclosure | emergency code on command line | medium | mitigate | Code only appears in the installer's own arguments and the --hash-code call (short-lived); only the PBKDF2 hash is persisted; installer never echoes it |
| T-07-15 | Elevation of Privilege | scheduled task at highest privileges | medium | accept | Required so the agent can lock and shut down Windows; task action path is under Program Files (not user-writable) |
| T-07-16 | Tampering | HKU hive load | low | mitigate | Temp hive always unloaded in a finally block with retry; script reports failure instead of leaving the hive mounted |
| T-07-SC | Tampering | npm/pip/cargo installs | high | accept | No new packages |
</threat_model>
