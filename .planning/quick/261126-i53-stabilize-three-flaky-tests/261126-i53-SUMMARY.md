# Quick 261126-i53 summary: stabilize three flaky tests

- **ReportPage**: the failure was a test bug. `DoesNotContain("cdn")` matched random antiforgery/base64 text. It now collects absolute URLs from src/href/srcset/action/poster/data, CSS url() and @import and fails on any non-loopback host. A unit test covers the extractor.
- **TvDriver standby**: the failure was a test bug (wall-clock polling under load). `SamsungTizenDriver.Time` (internal, `TimeProvider.System` by default, not from DI because the test host registers a manual FakeTimeProvider) drives the wake window and all pauses. The test uses `SteppingTimeProvider` and asserts exactly 12 reads before the key (1 + 10 polls + recheck) and that the key came after the 100 ms window.
- **TvSessionSink stop/start**: there was both a test race and a real race. Test race: the first power-on's Task.Run could start after Stop was queued, so it was dropped and the PowerOff legitimately ran first. Fixed with `FakeTvDriver.GateEntered`. Real race: each sink does async DB reads before `Enqueue`, so a slow, older Stop could be queued after a newer Start and power the TV off mid-session. Queued sink actions now re-check the station for a non-Ended session at run time (under the per-station queue slot) and skip power-off while one is open, or power-on when none is. `TvActionQueue._latest` now only moves forward. Two new tests cover a late Stop and a late Start signal.

Verification: the 6 targeted tests passed in 50/50 consecutive filtered runs with every core busy (`yes` per core). The full suite passed 1062/1062.
